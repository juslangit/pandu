A menu for every visitor

Pandu (Malay for guide) turns the plain list of links your server already renders into dropdowns, a mega-menu and a mobile drawer. One CSS file, one JavaScript file, {{SIZE_TOTAL}} gzipped, no framework, and every route keeps working as a normal link.

HTML structure

This is the whole contract. Class names are the API; IDs are yours to choose.

{{CODE "HTML structure"}}
Your brand Menu
Close
  • Journal
  • Rent gear
    • All rental gear
    • Tents and shelter
Book a trip
{{/CODE}}
  • Keep the panel straight after its trigger, inside the same <li>.
  • Without JavaScript the trigger stays a link to its section page, and panels open on hover and keyboard focus. With JavaScript it becomes a button, so put the section page inside the panel as its first link (pandu__overview). If you forget, the script adds one for you.
  • Mark the current page on the server with aria-current="page". A trigger whose panel holds the current page is underlined too.

    Your backend and routes

    Pandu has no router and never changes a URL. Render the same markup from whatever produces your pages today, and set aria-current where you already know the route. Three examples:

    {{CODE "Laravel Blade"}} routeIs('rent.index')) aria-current="page" @endif>All rental gear {{/CODE}} {{CODE "Django template"}} All rental gear {{/CODE}} {{CODE "plain PHP"}} >All rental gear {{/CODE}}

    If your templates cannot mark the current page, add data-pandu-current="auto" to the header and the script will match the link whose path equals the address bar.

    Building from JSON

    For a site whose menu lives in a CMS or an API, Pandu.mount() renders the same markup from a config object and starts it. Server-rendered HTML is still the better default, because it works before any script loads.

    {{CODE "JSON config"}} Pandu.mount(document.getElementById('nav-slot'), { brand: { label: 'Lereng', href: '/' }, items: [ { label: 'Trips', href: '/trips/', columns: [ { heading: 'Perak', links: [ { label: 'Gua Tempurung', href: '/trips/gua-tempurung/', desc: 'Half day' } ] } ], feature: { title: 'Kinta Valley loop', href: '/trips/kinta-valley/', image: '/img/lake.webp' } }, { label: 'Rent gear', href: '/rent/', links: [ { label: 'Tents', href: '/rent/shelter/' } ] }, { label: 'Journal', href: '/journal/' } ], cta: { label: 'Book a trip', href: '/book/' } }); {{/CODE}}

    Keyboard map

    KeyWide screensDrawer (phones)
    Tab / Shift TabMoves through items in reading order, into an open panel and out of it. Leaving a panel closes it. Never trapped.Cycles inside the open drawer; the page behind is inert.
    Enter / SpaceOn a trigger, opens or closes its panel. On a link, follows it.On Menu, opens the drawer. On a section, expands or collapses it.
    EscCloses the open panel and returns focus to its trigger.Closes the drawer and returns focus to the Menu button.
    → / ←Next or previous top-level item (wraps). From inside a panel, closes it and moves to the neighbouring item.Not used.
    ↓ / ↑On a trigger, opens the panel and focuses its first or last link. Inside a panel, next or previous link.Next or previous item in the drawer.
    Home / EndFirst or last top-level item, or first or last link in the open panel.First or last item in the drawer.

    When the drawer opens, focus moves to its first item. A click outside an open panel closes it, and following any link closes everything.

    Why the disclosure pattern, not role="menu"

    The WAI-ARIA Authoring Practices offer two ways to build site navigation. The menu pattern (role="menubar" and role="menu") is meant for application commands, like a desktop app's File menu. It tells a screen reader to switch into a mode where arrow keys are required, Tab skips over items, and links stop being announced as links. Visitors who expect a website do not expect that.

    The disclosure navigation pattern keeps a plain list of links inside a <nav> landmark, with a button that shows and hides each group. Tab works the way it does on every other page, links are announced as links, and arrow keys are an extra shortcut rather than a requirement. Pandu follows it.

    • The drawer is not given role="dialog" so the menu stays a navigation landmark. It behaves like a modal anyway: everything outside it is made inert, the page stops scrolling, and focus goes back to the Menu button on close.
    • Current page is shown with an underline as well as aria-current, never with colour alone.
    • Respects prefers-reduced-motion (no slides or fades) and Windows High Contrast (forced-colors: panels and buttons get system-colour borders).
    • Every target is at least 44 by 44 px, and the bar's height is fixed, so nothing shifts when fonts or the script load.

    Script API and events
